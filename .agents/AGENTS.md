# Habeas Corpus / Nyaya-Setu Architectural & Behavioral Rules

## 1. Knowledge Brain & Storage Locations
- **Vector Embeddings (FAISS):** Dense embeddings generated by `BAAI/bge-m3` are stored offline in `semantic_index/legal.index`.
- **Chunk Metadata:** The mapping from vector IDs to case text and statutes is stored in `semantic_index/metadata.json`. Do not recreate or store index files in alternative temporary directories.
- **Knowledge Graph (Neo4j):** Structural legal citations and hierarchy exist in remote Neo4j (configured in `.env` via `NEO4J_URI`).

## 2. Windows CP-1252 Encoding Guardrail
- The primary development OS is Windows using PowerShell with default CP-1252 terminal encoding.
- **NEVER** output non-ASCII or special Unicode characters (e.g., arrows `→`, checkmarks `✓`, or emojis) in standard Python `print()` statements or logger outputs, as they cause fatal `UnicodeEncodeError: 'charmap' codec can't encode character` crashes.
- Always use simple ASCII alternatives:
  - Use `->` instead of `→`
  - Use `[OK]` instead of `✓`
  - Use `[X]` instead of `✗`

## 3. Unified LLM Client Usage
- The system supports dual LLM providers: OpenRouter (`OPENROUTER_API_KEY`, defaulting to `google/gemini-2.5-flash`) and Google AI Studio (`GEMINI_API_KEY`).
- **NEVER** instantiate direct provider SDK clients (`google.genai.Client` or custom OpenRouter calls) within individual domain modules (e.g., Conversation, Query Understanding, OCR).
- **ALWAYS** import and call `call_llm()` from `reasoning.llm_client`:
  ```python
  from reasoning.llm_client import call_llm
  raw_json = call_llm(prompt, temperature=0.0, max_tokens=1024, json_mode=True)
  ```
- Always implement graceful fallbacks (e.g., regex extraction or rule-based mapping) when `call_llm()` returns `None`.
